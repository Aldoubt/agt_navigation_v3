# 导航启动文档

> 历史归档：2026-09-24 起默认里程计已切换为 FAST-LIO2；当前操作请见 [导航启动文档](../../导航启动文档.md)，不要按本归档中的默认后端启动。

> **V4 过渡期说明（2026-09-23）：** 本文后续部分仍含 V3 的默认地图和 RViz `Nav2 Goal` 直连示例。当前地图由 `--map auto --robot bunker_v1` 从 registry 解析；HMI 只是独立操作界面，不能代替后台启动。先用 `run_field_stack.sh --mode navigation --map auto --robot bunker_v1 --dry-run` 核对地图。实机导航须先完成 [V4 验收矩阵](docs/acceptance/V4_ACCEPTANCE_MATRIX.md)的发布门；验证 V4 控制链时，目标应走 `/navigation/navigate_to` 或 `/navigation/follow_route`，不要把 RViz `Nav2 Goal` 的直连结果当作 V4 Capability 验收。

脚本支持两个独立的选择：

- `--mode navigation|inspection`：纯导航，或到点拍照任务。
- `--lio-backend batch_lio|fastlio2`：默认 Batch-LIO，或第二种 FAST-LIO2 导航里程计。

两个里程计后端**互斥启动**，共享感知、全局重定位、Nav2、速度保护和车体 TF。
脚本自动加载 ROS 环境、按顺序启动组件，并在退出时按逆序关闭。省略
`--lio-backend` 时仍使用 Batch-LIO；原来的启动命令保持有效。

## 0. 首次使用新后端：先在宿主机更新构建

在宿主机 ROS 终端中执行；不要在运行中的导航进程上热切换后端：

```bash
cd /home/yangxuan/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
colcon build --symlink-install --executor sequential --packages-select \
  fastlio2 agt_batch_lio_adapter agt_fastlio_adapter \
  agt_global_relocalization agt_navigation_runtime agt_nav2_bringup \
  agt_rviz_patrol agt_system_bringup
source install/setup.bash
```

该构建不会主动启动机器人。更换后端前，先在旧启动终端按 `Ctrl+C` 正常停止，
确认旧 LIO/适配器退出，再启动新模式并在车辆静止时重新全局定位。不要保留旧
`map→odom` 校正去套用一个重新初始化的 odom 原点。

## 1. 导航模式一：Batch-LIO（默认）

不启动相机、巡检任务或图片保存：

```bash
/home/yangxuan/ros2_ws/src/agt_navigation_v3/scripts/run_field_stack.sh \
  --mode navigation --lio-backend batch_lio --rviz
```

看到 `[READY] Mode: navigation` 后，在 RViz 使用 `Nav2 Goal` 选择目标点。该工具直接
发送 `/navigate_to_pose` action，机器人会前往单个目标点。再次选择目标会提交新的导航
目标。纯导航模式没有 `/agt/rviz_patrol/start` 服务，也不会产生拍照任务目录。

## 2. 导航模式二：FAST-LIO2

```bash
/home/yangxuan/ros2_ws/src/agt_navigation_v3/scripts/run_field_stack.sh \
  --mode navigation --lio-backend fastlio2 --rviz
```

应看到 `lio_backend=fastlio2`（dry-run），实际就绪后看到
`[READY] LIO backend: fastlio2`。仍在 RViz 使用 `Nav2 Goal`，不需要换导航 action。

脚本会在 Nav2、RViz 和启动检查完成后，给 FAST-LIO 最多 15 秒恢复窗口，并要求
Localization Manager 连续三帧保持 `LOCALIZED`。已接受的 `map→odom` 全局修正仍有效时，
瞬时里程计陈旧只会等待恢复，不会再触发第二次全局重定位。如果 15 秒后仍不稳定，
脚本会保守退出并打印当前状态，而不是清空已成功的全局修正再重新匹配。必须等到最终
`DEMO PREFLIGHT PASS` 和 `[READY]` 后再发送目标。

| 合同 | Batch-LIO | FAST-LIO2 |
|---|---|---|
| 前端节点 | `/laserMapping` | `/fastlio2/lio_node` |
| 原始里程计 | `/aft_mapped_to_init` | `/fastlio2/lio_odom` |
| 适配器 | `/agt_batch_lio_adapter` | `/agt_fastlio_adapter` |
| 导航里程计 | `/agt/odometry/local` | 相同 |
| 导航动态 TF | `odom→base_footprint` | 相同 |
| 适配器就绪/延迟 | `/agt/odometry/adapter_status` | 相同 |
| 全局 TF 唯一发布者 | Localization Manager | 相同 |

FAST 模式只启动本地 LIO，不启动 PGO/HBA 或建图保存节点。原始 Livox CustomMsg
与 IMU 直接送入前端，局部障碍点云过滤仍在独立支路上，不得串到 LIO 输入之前。

关键约束：

- FAST 前端与适配器使用相同的 `use_sim_time`。
- `world_frame=odom`、`body_frame=body`、`esti_il=false`，不允许在线改变适配器缓存的外参。
- 适配器自动使用所选 FAST 配置中的 `r_il/t_il`，再与 URDF 挂载 TF 组合；全局重定位
  同步使用这份冻结标定。不要把 Batch YAML 的平移正负号手工抄入 FAST 配置。
- 当前 FAST 上游没有填写角速度；导航适配器从转换后的连续 base 位姿生成线/角速度，
  正确包含参考点偏移。首帧或长时间间断后的首帧不会用于差分。
- 保留 200 ms 陈旧数据门限，不给旧位姿伪造新时间戳；TF 缺失时不发布一半转换结果。
- FAST 前端的 LiDAR 订阅只保留最新 1 帧，IMU 订阅保留 400 帧。这样在系统短时调度
  抖动后会恢复到最新扫描，同时保留跨越该间断的高频 IMU 样本；不要把 LiDAR 深度改回
  10，否则完整定位栈下可能连续回放约 1 秒前的扫描并触发陈旧数据门限。
- 沿用现有 FAST 原生 IMU 处理：其加速度回调有 `×10.0`，内部重力为 `9.81`。首次实车
  验收前需核对 MID360 单位、静止偏置和倍率；本次没有擅自修改共享建图前端的算法参数。
- 就绪检查仍需连续三次 FRESH 和有效全局定位。FRESH 只说明新鲜度，不保证几何精度；
  新后端必须经过现场静止/转向/路径验证，不能把离线单测通过当作实车验收。

每次实际启动都会在运行目录保存 `launch_selection.txt` 和 `lio_config_input.yaml`。
FAST 还会生成 `agt_fastlio2_*/fastlio2.yaml` 临时快照，用于保持实际输入话题和外参一致。
需要试验参数时可使用 `--lio-config /absolute/path/to/fastlio2.yaml`；该文件必须是所选
后端自己的格式。离线测耗时时可以在 FAST 配置启用 `print_time_cost`，但现有两段
短探针包不含原始雷达点云，不能据此重跑前端。

## 3. 到点拍照保存模式

启动相机云台、巡检任务和图片归档：

```bash
/home/yangxuan/ros2_ws/src/agt_navigation_v3/scripts/run_field_stack.sh \
  --mode inspection --rviz
```

拍照模式同样可以加 `--lio-backend fastlio2`，例如
`run_field_stack.sh --mode inspection --lio-backend fastlio2 --rviz`。省略后端仍使用 Batch。

看到 `[READY] Mode: inspection` 后：

1. 在 RViz 使用 `2D Goal Pose` 依次点击任务点；此时只加入队列，机器人不会立即运动。
2. 每个绿色箭头代表一个已加入的任务点。
3. 全部点选完成后，在另一个终端启动任务：

```bash
ros2 service call /agt/rviz_patrol/start std_srvs/srv/Trigger '{}'
```

任务执行顺序为：

```text
记录当前起点
  -> 导航到任务点
  -> 确认底盘实测停止
  -> 左/中/右三视角拍照并保存
  -> 下一个任务点
  -> 返回起点
```

清空尚未启动的任务点：

```bash
ros2 service call /agt/rviz_patrol/clear std_srvs/srv/Trigger '{}'
```

取消正在执行的巡检任务：

```bash
ros2 service call /agt/rviz_patrol/cancel std_srvs/srv/Trigger '{}'
```

正式结果保存在：

```text
~/.ros/agt_inspection_records/<mission_id>_<timestamp>/
```

任务点、相机角度和文件结构见
[云台相机任务与导航点设置说明.md](云台相机任务与导航点设置说明.md)。

## 4. 停止程序

在运行脚本的终端按一次 `Ctrl+C`。脚本会停止 RViz、导航、定位和硬件进程。运行日志
保存在：

```text
~/.ros/agt_field_stack/<timestamp>/
```

不要直接关闭终端或在录包尚未结束时断电。

## 6. 启动前最低检查

- MID360 地址 `192.168.1.117` 可以 ping 通。
- `can0` 已启动，遥控器/急停和人工接管可用。

- 车辆静止后再执行全局重定位。
- 只有定位状态为 `LOCALIZED` 且 RViz 中位姿正确时才发送目标。

## 8. 路径贴墙和动态障碍残影

当前实机参数使用以下策略：

- 全局代价地图膨胀半径为 `1.00 m`，规划器提高了穿越高代价区域的惩罚，优先选择通道中部。
- 局部代价地图膨胀半径为 `0.85 m`，与控制器的减速距离和代价衰减参数一致。
- `/agt/navigation/points_obstacles` 只负责标记障碍。
- `/agt/livox/points` 只负责射线清除，保留地面和背景回波用于清除行人离开后的旧体素。
- 局部地图更新频率为 `10 Hz`，RViz 发布频率为 `5 Hz`。

修改配置后必须重新启动整套程序。现场先让机器人保持静止，让人员在车前经过后离开，
观察局部代价地图中的人体轮廓是否在后续背景回波到达后快速消失。若障碍已经离开但局部
地图仍长时间保留，可在机器人静止时手动清空一次局部地图：

```bash
ros2 service call /local_costmap/clear_entirely_local_costmap \
  nav2_msgs/srv/ClearEntireCostmap '{}'
```

清空后真实障碍会由后续 LiDAR 帧重新标记。如果路径仍持续贴墙，应保存当次日志和地图截图，
检查静态地图中的散点、未知区域和错误墙线，不要继续盲目扩大膨胀半径。

## 10. FAST-LIO2 左右摆头收敛参数（2026-09-22）

后方屏蔽后的复测包：

包长 297.69 s。后方碰撞报警和控制器碰撞 abort 均为 0，但车辆前进时仍有 53 次稳定的

- 实车验证巡航速度由 0.45 m/s 降至 0.40 m/s；
- 速度平滑器和最终命令保护仍限制角加速度为 0.8 rad/s²。

## 11. 全局规划、LIO、轮速轨迹和手画路线

导航模式的默认 RViz 配置同时显示四条路线：

| 颜色 | 话题 | 含义 |
|---|---|---|
| 红色 | `/plan` | Nav2 当前全局规划 |
| 蓝色 | `/agt/path_tool/lio_path` | `map` 坐标系中的 LIO 实际路线 |
| 绿色 | `/agt/path_tool/wheel_path` | 从起点对齐到 `map` 的轮速相对路线 |
| 橙色 | `/agt/path_tool/route` | 操作员点画并即将执行的路线 |

绿色路线只在起点进行一次刚性对齐。履带打滑和轮速航向积分误差会逐渐积累，因此绿色与
蓝色分开是底盘里程计误差证据，不能把绿色路线当成地图中的绝对位置。

需要车辆沿指定线形行驶时，在 RViz 工具栏选择 `Publish Point`，从车辆前方向终点依次
点击折线顶点。点击完成后执行：

```bash
ros2 service call /agt/path_tool/start std_srvs/srv/Trigger '{}'
ros2 topic echo /agt/path_tool/status
```

节点先将折线按 `0.05 m` 间距插值，并调用 Nav2 `/is_path_valid`，用完整车体 footprint
检查全局代价地图。只有整条路线有效才提交 `/follow_path`；执行时仍由现有 RPP、局部动态
障碍检测、速度平滑器和底盘命令保护负责安全控制。该方式不会调用全局规划器重新选择一条
靠墙捷径。它也不会自动绕过画在线上的障碍；预检发现碰撞会拒绝启动，行驶中出现动态障碍
时控制器会停车或中止，需要清障或重新画线。

操作命令：

```bash
# 清除尚未执行的橙色路线
ros2 service call /agt/path_tool/clear_route std_srvs/srv/Trigger '{}'

# 取消正在执行的手画路线
ros2 service call /agt/path_tool/cancel std_srvs/srv/Trigger '{}'

# 清空蓝色和绿色历史轨迹，开始新的对比
ros2 service call /agt/path_tool/clear_trails std_srvs/srv/Trigger '{}'
```

使用 RViz `Waypoint / Nav Through Poses Mode` 只是在多个点之间继续调用全局规划器，规划器
仍可能切角或选贴墙路线，因此它不等价于沿手画折线行驶。

## 12. 离线查看手画路线交互

关闭实车导航栈后，可只启动地图、静态机器人位姿、手画路线节点和 RViz：

```bash
cd /home/yangxuan/ros2_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch agt_rviz_patrol path_tool_offline.launch.py
```

离线窗口使用当前默认的大地图，不启动雷达、底盘驱动、定位、规划器或控制器，也不会发布
运动命令。交互步骤：

1. 在 RViz 工具栏选择 `Publish Point`。
2. 从机器人附近向终点依次点击折线顶点。
3. 橙色 `/agt/path_tool/route` 显示当前手画路线。
4. 调用预览服务查看插值后的最终线形和状态：

```bash
ros2 service call /agt/path_tool/start std_srvs/srv/Trigger '{}'
ros2 topic echo /agt/path_tool/status --once
```

离线模式的返回信息包含 `offline preview`，仅生成 `0.05 m` 间距的路线，不执行
`/is_path_valid`，也不提交 `/follow_path`。清空后可重新画线：

```bash
ros2 service call /agt/path_tool/clear_route std_srvs/srv/Trigger '{}'
```

默认机器人预览位置为地图中的 `(0, 0, 0)`。需要从其他位置观察路线连接效果时：

```bash
ros2 launch agt_rviz_patrol path_tool_offline.launch.py \
  robot_x:=10.0 robot_y:=-5.0 robot_yaw:=1.57
```

离线预览中不要使用 `Nav2 Goal` 或 `Waypoint / Nav Through Poses Mode`，因为对应的 Nav2
action server 没有启动。完成后在启动终端按 `Ctrl+C` 退出。
