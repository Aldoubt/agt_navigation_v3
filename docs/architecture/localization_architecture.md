# AGT Localization Framework v1 Architecture

## 1. Overview

AGT Localization Framework is a modular 3D LiDAR localization framework designed for outdoor mobile robots.

The goal is to provide:

- Global relocalization without initial pose
- Continuous high-frequency odometry tracking
- Low-frequency map-based correction
- Large-scale map runtime management
- Stable ROS2 TF integration

The architecture is inspired by modern LiDAR localization systems such as Lightning-LM, while maintaining AGT's modular separation between:

- Mapping
- Localization
- Navigation


---

# 2. Design Principle


The system follows the principle:


```
Global Localization
 |
 |
 map -> odom
```
    +
```
LIO Odometry
 |
 |
 odom -> base_link
```
    +
```
Local Map Correction
 |
 |
 update map -> odom
```


Localization does not replace odometry.

Localization provides global consistency.

Odometry provides real-time motion continuity.

# 5. Module Description


## 5.1 Localization Manager


Responsibility:

- Maintain localization state
- Publish map -> odom TF
- Manage initialization and recovery


States:


```
UNINITIALIZED
```
  |
```
SEARCHING
```
  |
```
LOCALIZED
```
  |
```
TRACKING
```
  |
```
LOST
```



Only Localization Manager can publish:


```
map -> odom
```



---

# 5.2 Global Relocalization


Purpose:

Solve:

"Where am I?"


Input:


```
LiDAR cloud
Map Package
(optional IMU attitude)
```


Pipeline:


```
Point Cloud
```
  |
```
Polar Context descriptor
```
  |
```
Candidate retrieval
```
  |
```
3D-BBS search
```
  |
```
small_gicp refinement
```
  |
```
Initial pose
```


Output:


```
T_map_base
```


Used during:

- startup
- localization lost recovery


---

# 5.3 Keyframe Manager


Inspired by Lightning-LM.


Do not match every LiDAR frame.

Use LIO keyframes.


Keyframe:


```
timestamp
pose
cloud
covariance
quality
```



Generated by:


- distance threshold
- rotation threshold
- time threshold


Example:


```
distance > 1m
or
yaw > 5deg
or
time > 2s
```


---

# 5.4 Map Runtime Server


Purpose:

Separate map storage and localization.


Localization should not directly access PCD files.


Interface:


```
GetLocalMap()
```


Input:


```
robot pose
radius
layer
```


Output:


```
local point cloud
map metadata
```



Future support:


- tiled map
- dynamic layer
- elevation layer


---

# 5.5 Local Tracker


Purpose:

Long-term drift correction.


Input:


```
LIO Keyframe
- 
Local Map
```


Output:


```
T_map_base correction
score
quality
```


Default:


```
small_gicp
```


Plugin interface:


```
RegistrationPlugin
```
|
+ small_gicp

+ NDT

+ VGICP
```
```


---

# 5.6 Correction Filter


Purpose:


Prevent wrong registration causing TF jumps.



Input:


```
T_match
T_current
```


Output:


```
T_filtered
```


Constraints:


```
max_translation_update
max_rotation_update
smooth_time
```


Use:


SE(3) interpolation
